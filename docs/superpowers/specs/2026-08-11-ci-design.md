# CI 自动编译测试（GitHub Actions）设计

日期：2026-08-11
状态：已批准

## 背景与目标

开源仓库 `Edisonwei54/EasySnipLite`（.NET 10 / WPF / 单测 xUnit）目前没有 CI。
目标：提交 PR 后自动编译 + 跑全部单测，`push` 到 main 时兜底再跑一遍，结果反映在 PR 检查 / commit 状态上。

## 约束

- 主程序与单测都面向 `net10.0-windows`（WPF），**必须用 Windows runner**。
- CI runner 为无交互桌面会话（session 0），截图/热键类 E2E 无法运行——本 CI **只做编译 + 单测**，不做 `verify-m7.ps1` 类发布冒烟。
- `global.json` 版本锁定不得破坏本地构建（本地 SDK：10.0.302）。

## 方案

### 1. `.github/workflows/ci.yml`

单 workflow、单 job：

- **触发**：
  - `pull_request`：所有 PR（含从 fork 来的，PR 检查 + 分支保护）
  - `push`：`main` 分支
- **Job `build-test`**，runner `windows-latest`：
  1. `actions/checkout@v4`
  2. `actions/setup-dotnet@v4`：`dotnet-version: 10.0.x`，开启 NuGet 包缓存
  3. `dotnet restore EasySnipLite.slnx`
  4. `dotnet build EasySnipLite.slnx -c Release --no-restore`
  5. `dotnet test EasySnipLite.slnx -c Release --no-build --logger "trx;LogFileName=test-results.trx" --results-directory TestResults`
  6. `actions/upload-artifact@v4`：上传 `TestResults/`（测试失败时方便下载 TRX 排查）
- 任一 step 失败即 job 失败 → PR 检查标红。

### 2. `global.json`（仓库根）

```json
{
  "sdk": {
    "version": "10.0.302",
    "rollForward": "latestFeature"
  }
}
```

- 本地：精确命中 10.0.302，构建行为不变。
- CI：`setup-dotnet` 装最新 10.0.x，`latestFeature` 允许滚动到更高 band。
- 消除「本地能跑、CI 挂了」的 SDK 版本漂移问题。

### 3. README badge

标题下方加 GitHub Actions 状态徽章：

## 不做的事（明确排除）

- 多 OS 矩阵（WPF 仅 Windows，无价值）。
- `dotnet publish` / 发布冒烟（无交互桌面，跑不了）。
- 代码覆盖率报告（单测全为纯逻辑，coverlet 已引用，作为将来可选项）。

## 验证方式

- 本地：`dotnet build` / `dotnet test` 全绿（改动只涉及新文件，构建行为不变）；YAML 语法自查。
- 真实验证：PR 创建后 workflow 自动在 PR 上运行，绿色即验证通过；合并进 main 后 `push` 触发再次确认。
